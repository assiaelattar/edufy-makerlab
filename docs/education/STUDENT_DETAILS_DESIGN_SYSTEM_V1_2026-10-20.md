# Student Details — Design System v1 completion audit

Date: 2026-10-20. Scope: the Student Details route and its local child workspaces, forms and dialogs. This is an isolated local candidate; it has not been pushed or deployed.

## What changed

- Brought Overview, Learning, Attendance, Finance and Access child surfaces into the existing `data-edu-system="1"` contract. The styling uses the approved neutral records, green learner identity, blue operations, orange attention and purple learning cues in both school themes.
- Kept the real student, enrollment, project, attendance and finance selectors and their existing write handlers. The 011Y priority is derived from actual missing contact, balance and attendance state. The student preview uses recorded skills and published projects; it no longer invents XP or a level.
- Used the shared Design System modal frame for Student Details, enrollment certificates, payment proof, parent access and quick access. Added accessible names to icon actions and labels to edit fields. Learning's nested choice now has `aria-pressed`; the primary section tabs retain keyboard tab semantics.
- Matched visible edit, enrollment, deletion, PIN and quick-link controls to the route's existing permission checks. The read-only synthetic role shows the record without mutation controls.
- Fixed two narrow-screen issues: focus no longer scrolls the hero internally after the editor closes, and a failed-save alert remains above the sticky form footer.

## Workflow completion pass — 2026-10-20

- The learner route now accepts only a student record verified against the signed-in UID and organization. It no longer falls back to a route-supplied ID or email match. Enrollments and published projects accept only canonical or authenticated UID ownership aliases. The dedicated learner data listener resolves that link before subscribing to owner-scoped records; the Firestore emulator confirms the scoped enrollment/project queries and denies the organization-wide student query.
- Enrollment edit now checks grade/group membership and nonnegative tuition, clears stale group choices when a level changes, keeps the draft on failure, and prevents duplicate saves. Payment edit checks positive amount, check details and transfer proof; its payment and enrollment-balance updates commit atomically. Payment deletion also uses a batch for the linked balance and payment removal. The App-owned Record Payment handler checks positive amount and method details before writing, with a duplicate-submit guard.
- Schedule sharing uses actual active enrollment times and no longer places stored credentials into the WhatsApp draft. Opening a share draft does not mark the schedule or receipt as sent; an operator must confirm after sending. Account-sharing drafts omit the stored learner password, and access actions are hidden or restricted according to existing role checks. Blocked certificate popups show a warning while preserving the dialog.
- Finance's pale metric cards now retain readable amounts in dark mode. The redundant mobile payment-card click was removed; its named audit button remains. The synthetic desktop dark browser review covered empty state, Finance contrast, read-only Access, transfer payment edit and enrollment edit. Evidence: `evidence/student-details/desktop-dark-*-workflow.png`.

The actual payment edit handler passed `node views/student-details/studentPaymentEdit.smoke.mjs` for atomic writes, failure/retry, duplicate submit and cash-to-transfer balance. The App-owned payment submission handler passed an isolated execution harness for invalid input and duplicate submit. `node scripts/check-education-system.mjs` passes 27 checks. The learner Firestore emulator passes 19 synthetic assertions with storage skipped. `npm.cmd run build` passes with 2,429 transformed modules; `git diff --check` passes. The existing mixed Firebase import and large chunk warnings remain.

The synthetic fixture is not a signed-in school or physical-phone test. It cannot verify real tenant totals, account permissions, Firestore persistence, external delivery, certificate print styling or the downstream Activity Details proof overlay. Official certificate templates retain their established branding until an approved document reference is supplied. Stored `loginInfo.initialPassword` and credential lifecycle need a separate authenticated account migration; this pass removes it from share drafts but does not rotate, remove or stop the existing reveal control. New payment creation still uses its existing create-then-balance sequence; a failed balance write can leave a recorded payment that needs reconciliation. No production data, account, or security rule was changed.
