# Student Details — Design System v1 completion audit

Date: 2026-10-20. Scope: the Student Details route and its local child workspaces, forms and dialogs. This is an isolated local candidate; it has not been pushed or deployed.

## What changed

- Brought Overview, Learning, Attendance, Finance and Access child surfaces into the existing `data-edu-system="1"` contract. The styling uses the approved neutral records, green learner identity, blue operations, orange attention and purple learning cues in both school themes.
- Kept the real student, enrollment, project, attendance and finance selectors and their existing write handlers. The 011Y priority is derived from actual missing contact, balance and attendance state. The student preview uses recorded skills and published projects; it no longer invents XP or a level.
- Used the shared Design System modal frame for Student Details, enrollment certificates, payment proof, parent access and quick access. Added accessible names to icon actions and labels to edit fields. Learning's nested choice now has `aria-pressed`; the primary section tabs retain keyboard tab semantics.
- Matched visible edit, enrollment, deletion, PIN and quick-link controls to the route's existing permission checks. The read-only synthetic role shows the record without mutation controls.
- Fixed two narrow-screen issues: focus no longer scrolls the hero internally after the editor closes, and a failed-save alert remains above the sticky form footer.

## Validation

- `npm.cmd run build`: passed, 2,429 modules. Existing mixed Firebase import and large chunk warnings remain.
- `node scripts/check-education-system.mjs`: passed, 27 checks.
- `git diff --check`: passed.
- No `agent:check` script exists in this repository; the focused Design System check above is the available repository gate for this slice.
- Browser fixture: desktop and exact 390 px mobile, light and dark. All 13 distinct Student Details dialog families were opened in each combination: editor, schedule, enrollment edit, two certificates, project detail, payment proof, invoice, payment edit, parent choice, parent password, manual QR and one-click access. At desktop the dialogs were 444/668 px wide with matching internal scroll widths; at 390 px they were 371 px wide with matching internal scroll widths. The page had no horizontal overflow. `prefers-reduced-motion: reduce` made the tested modal animation and transition `1e-05s`, and editor initial focus reached an input. No school service is connected to the fixture.
- The `/forms` fixture checked the App-owned payment modal and actual enrollment wizard at 390 px dark; the wizard’s four steps had no internal horizontal overflow after its grid fix. Payment unselected choices now retain readable contrast in both themes. Screenshots: `mobile-390-dark-app-payment.png`, `mobile-390-dark-app-enrollment.png`.

## Acceptance boundary

The actual local app at `http://127.0.0.1:5202/` showed the public MakerLab Academy landing page in the earlier browser pass. No existing signed-in IAB tab was available for this follow-up, and no designated school session was supplied. Therefore this pass does **not** claim real-account Student Details visual, data, route restoration, permission or App-owned submit-handler acceptance. A staff reviewer should inspect populated and empty records in both themes on desktop and a physical phone, return to the Students register to confirm filter/scroll restoration, and exercise safe test-record saves only in an authorized non-production environment. The Activity Details proof overlay and previously documented retained learner password issue are separate follow-ups.
