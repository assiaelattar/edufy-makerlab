# Parent access hosting audit — 11 October 2026

**Verdict: NOT RELEASE READY.** This audit and local configuration change did not deploy code, rules, indexes, credentials, or accounts.

## Hosting evidence

- The intended public layout has two separate frontends: Edufy at `https://edufy.makerlab.academy/` on Hostinger and SparkQuest at `https://sparkquest-makerlab.vercel.app/` on its own Vercel project. `https://sparkquest.makerlab.academy/` is a future custom domain after acceptance, not a current release dependency. The Edufy Vercel deployment uses the Edufy GitHub codebase as its source and is the intended host for the trusted parent-access API.
- The registered Edufy frontend is `https://edufy.makerlab.academy/` on Hostinger and deploys from `origin/main`. Its `public/.htaccess` serves the static SPA and has no `/api/parent-access` reverse proxy. A relative browser request to that path cannot execute the Admin SDK handler there.
- The repository has root `api/` functions, including `api/agent/health.js`, and `vercel.json` with an SPA catch-all. Vercel documents root `api/` files as Functions for Vite projects and gives filesystem routes precedence over rewrites. The existing Edufy Vercel project is therefore the smallest plausible trusted target for `api/parent-access/index.js`.
- The user attached the correct Chrome profile on 11 October 2026. The owning team is `platformmakerlab-5357s-projects`, and both `edufy-makerlab` and `sparkquest-makerlab` are manageable there. The local Vercel CLI is authenticated as `platformmakerlab-5357` and the clean worktrees are linked to those existing projects without changing a deployment.
- `edufy-makerlab` uses Vite, an empty Root Directory setting, default build commands, and Node 24.x. Although it serves code from the same GitHub codebase as official Edufy, its current Vercel settings show no connected Git repository and its current production deployment came from the Vercel CLI. A push to `origin/main` therefore does not automatically deploy this API or prove the two sites run the same commit. Production Config `EDUFY_PARENT_ACCESS_ALLOWED_ORIGINS` is set; no Firebase Admin credential option is configured yet, so the Function cannot initialize Firebase Admin.
- `sparkquest-makerlab` is a separate Vite, CLI-deployed project with an empty Root Directory setting and no Git connection. Its only visible project variable name at audit time was `GEMINI_API_KEY`; no value was read. The empty setting does not establish which local folder was uploaded by the CLI.
- The Audit Hub's read-only live probes on 10 October 2026 at 22:34 UTC returned `200 text/html` for `/api/parent-access` on both Hostinger and `edufy-makerlab.vercel.app`. The Vercel `/api/agent/health` probe returned `500` JSON with `agent_token_not_configured`, matching this repository's `api/agent/_lib/auth.js` error code. This shows the Vercel project executes API Functions while the parent handler is **not deployed** at its expected path. A fresh browser GET also rendered the Edufy landing page at that Vercel parent path. The execution shell and web fetcher separately failed DNS, so the Audit Hub and browser observations supply the live evidence.
- After a scoped API deployment, an unauthenticated GET should return the parent handler's `405` JSON, and an allowlisted OPTIONS request should return JSON/CORS headers. SPA HTML, a Vercel 404, or a function error leaves the route unverified. The agent health response does not prove that Firebase Admin credentials are present for parent access.

## Local routing and origin configuration

- `services/parentAccess.ts` accepts `VITE_PARENT_ACCESS_API_ORIGIN` as a complete HTTPS origin. If unset, it uses the existing ERP URL resolver: the local Edufy origin during development and `https://edufy-makerlab.vercel.app` on a public host. Plain HTTP is accepted only for localhost in a development build. The value is a public build setting, never a service credential.
- `api/parent-access/index.js` now checks browser `Origin` against exact values in server-only `EDUFY_PARENT_ACCESS_ALLOWED_ORIGINS`. It rejects unlisted origins before Firebase Admin initialization and handles an allowlisted CORS preflight. The Firebase ID token, active staff role, tenant, and learner checks remain the authorization boundary; CORS alone does not authorize account changes.
- For the Vercel API serving the Hostinger frontend, the current client resolver defaults to `https://edufy-makerlab.vercel.app`; use the public build override only if that API origin changes. The API allowlist includes the exact official Edufy origin `https://edufy.makerlab.academy` and its Vercel origin. For a same-origin Node/proxy deployment, allowlist that exact origin. Do not use a wildcard.
- No `vercel.json` rewrite was changed: root API Functions already work on the Vercel project, and the catch-all currently serves HTML only because the parent Function is absent there. Confirm the deployment's Git project/root and Function artifact before release. The local `scripts/agent-dev-server.js` does not yet route `/api/parent-access`; the isolated emulator and origin smoke are the current local proofs.
- The clean candidate at `.release-worktrees/parent-access-20261011` is based on `origin/main` `f1b5810`. Root production build, SparkQuest TypeScript, SparkQuest production build, endpoint syntax, origin policy, three family domain smokes, and the read-only Pickup lifecycle smoke pass.

The isolated `demo-parent-access` suite passes issuance, alias collision, sibling linking, role and tenant denial, reset, and plaintext checks when `FIREBASE_PROJECT_ID=demo-parent-access` is supplied to the Admin SDK helper.
