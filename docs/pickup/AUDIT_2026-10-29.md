# Pickup end-to-end correction — 2026-10-29

Base: origin/main a9de61f. Isolated branch codex/pickup-end-to-end-20261029. Original Edufy checkout and Instructor Pass worktree are untouched. Tests use synthetic data only.

## Evidence and decisions

- Existing main already restricts the lobby to present/late attendance and removes confirmed pickups. Release remains visible pending parent receipt. Preserve this distinction and test it.
- Both active linked parents already have arrival/cancellation authority. The initiator remains immutable and private notes remain restricted to the initiating parent and learner.
- Previous receipt rules required the guardian profile name to equal the chosen picker. That blocked receipt for an authorized third-party pickup. New rule requires an active, same-tenant parent with an exact active Pickup guardian link. Staff and learners cannot substitute for parent receipt. The chosen authorized person and staff verification remain recorded.
- Verification note was mandatory in UI, adapter and rules. It is now optional (empty string recorded), bounded to 500 characters. Staff still selects verification method and attests physical verification.
- Parent shell now retains live status notices for every authorized child, including a direct link to receipt and cancellation messages. Existing optional original three-note sound is reused; no Duolingo asset copied. Confirmation displays Bonne route.
- Structured program schedule blocks now take precedence over stale enrollment schedule text in the daily roster. Existing eligibility and tenant checks retained.
- Learner reminder appears in the final ten minutes to save project proof. A dismissible Pickup prompt appears at end time, without forced navigation or submission. Missing end times produce no invented reminder.
- Admin lobby opens automatically only while already in Pickup, visible, idle for 30 seconds and with no focused editor/dialog. Other pages retain their work and receive a button. Opening is deferred during staff verification or a pending write.
- Released requests from the previous date remain accessible for the outstanding receipt. Learner listener rolls over at midnight.

## Boundaries requiring explicit acceptance

- Picker choices still use the academy-maintained parentName + authorizedPickups list. A guardian link alone contains no display name and does not add that person to the physical pickup list. Both parent names must be recorded as authorized pickup people; no identity is inferred from an email or alias. Automatically enumerating all linked parent identities would require a separate trusted projection/API.
- Schedule reminders use configured recurring timetable blocks, not Instructor Pass one-off overrides (separate integration is ongoing). A configured end time is required. Presence is required for the admin prompt; learner reminder is timetable-based.
- Cancellations retain their immutable daily history and require staff follow-up. This patch does not silently reopen a cancelled deterministic daily record.
- Sounds are optional foreground Web Audio cues after user activation. Background/locked mobile sound or delivery is not guaranteed; this is not an OS push service. Reference: https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices
- Real-family writes are prohibited during this QA. Physical-phone and authenticated device acceptance remain separate from synthetic evidence.
